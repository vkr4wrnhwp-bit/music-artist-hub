# Deploying everything in this repository

Five separate products live here. They share nothing but the repository and
`render.yaml`, which deploys all of them in one Blueprint apply.

| Service | What it is | Render type | Cost |
|---|---|---|---|
| `trace` | TRACE — motocross telemetry & tuning platform; app **and** team sync server on one origin | Node web service | paid (persistent disk) or free without it |
| `reach` | REACH — music discovery, opportunity intelligence and outreach | Python web service | paid (SQLite on disk) |
| `masterclip` | MASTERCLIP OS — cinematic AI-video render factory | Docker web service | paid (renders + database on disk) |
| `royalty-sweep` | Royalty Sweep — the royalty dashboard this repo started as | Python web service | free |
| `holeshot-tuner` | Holeshot Tuner — single-file fuel-map worksheet | Static site | free |

## Deploy (desktop, ~10 minutes)

1. [dashboard.render.com](https://dashboard.render.com) → **New → Blueprint**.
2. Connect this GitHub repository. Render reads `render.yaml` and lists all
   five services.
3. Render prompts for the values it will not invent (`sync: false` in the
   blueprint). Have these ready:
   - **REACH** — `REACH_PRINCIPAL_EMAIL` (who REACH acts as) and
     `REACH_ACCESS_KEY` (leave blank to keep `/reach` open, or set one and
     every screen asks for it once per browser).
   - **MASTERCLIP** — `SEED_EMAIL` and `SEED_PASSWORD` for the owner account
     that is created at boot, before anything is listening. Set these: the
     first account to hit signup claims the organization, and on a public URL
     that is a race against the internet.
   - Secrets marked `generateValue: true` (encryption and signing keys) are
     generated by Render and kept — you never see or choose them.
4. **Apply.** First build takes a few minutes; Masterclip's Docker image
   (ffmpeg) is the slowest. Each service gets its own
   `https://<name>-xxxx.onrender.com` URL, listed on the dashboard.

### Cost, stated plainly
`trace`, `reach` and `masterclip` each request a persistent disk, which
requires Render's cheapest paid instance type — three paid instances if you
deploy all three. `royalty-sweep` and `holeshot-tuner` are free.

To trial the paid ones at zero cost, delete that service's `disk:` block and
`plan:` line before applying. Everything still runs, but server-side data
resets on every deploy, restart and idle spin-down. Read the per-service notes
in `render.yaml` first — REACH's warning is the serious one: losing its
database means losing the suppression list, i.e. the record of who opted out
of contact. Do not send real outreach from a free instance.

Free instances also sleep when idle; the first request after a quiet period
takes ~30–60 seconds to wake. Normal, not a fault.

## First run of TRACE (do this in one sitting)

1. Open the `trace` URL. The page **is** the app.
2. Sign in as an admin or manager (Alex Ferro / Sam Calloway). The first
   sign-in **sets that account's password** and claims the organization.
3. **More → Team Sync** — the server URL is prefilled with the site's own
   origin. Enter the password, **Sign in to server**, then **Sync now**.
   The footer reading `synced to team server (rev 1)` means it worked.
4. From then on the bootstrap door is closed: new accounts need one-time
   invite codes from **More → Team & roles → Invite**. External tuners never
   get accounts — mint a grant token on the Remote Tuner Access screen and
   send them the URL / org id / token trio for `#/grantview`.

## Smoke test after deploy

- `https://<trace>/` renders the app (dark UI, circuit logo, SIMULATED banner);
  `https://<trace>/orgs/x/db` returns a JSON 401 — the API is gated.
- `https://<reach>/healthz` returns OK.
- `https://<masterclip>/api/health` returns OK.
- `https://<royalty-sweep>/` redirects to `/dashboard` and renders.
- `https://<holeshot-tuner>/` renders the tuner.

## After deploy

Auto-deploy is on: every push to `main` rebuilds the affected services — the
`buildFilter` blocks keep an edit in one product from rebuilding the others.
TLS is automatic on all of them, which is what TRACE's bearer tokens require.
Custom domains, backups and the account lifecycle: `mx-lab/docs/architecture/deployment.md`.
